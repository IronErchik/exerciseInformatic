Pull request —
приглашение к диалогу.

В pull request видны изменения между ветками. Участники могут задавать вопросы, оставлять комментарии к строкам кода и предлагать правки.

Когда обсуждение и необходимые проверки закончены, изменения можно объединить с основной веткой.

ГЛАВА 03 / GITHUB ACTIONS

Вы создаёте.
Actions проверяет.

Опишите повторяемые задачи в workflow: по событию GitHub
запустит их на runner — машине, которая выполняет задания.

СОБЫТИЕ → WORKFLOW → РЕЗУЛЬТАТ

Маленький файл.
Полезная привычка.

Workflow хранится в YAML-файле в папке .github/workflows/. В примере каждый push запускает задание с одной командой.

  1. 01
    Событие

    Новый push запускает workflow.

  2. 02
    Задание

    Runner с Ubuntu выполняет шаги.

  3. 03
    Результат

    Лог показывает, что произошло.

hello.yml
name: Hello workflow
on: [push]

jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - name: Say hello
        run: echo "Hello, GitHub!"
.github/workflows/hello.yml
ПОСМОТРИТЕ НА ПРОЦЕСС

Нажмите. И всё начнётся.

Учебная симуляция запуска — прямо в браузере.

○ Ожидает запускаhello.yml · push
  1. ○ Подготовка runner —
  2. ○ Say hello —
  3. ○ Завершение задания —
Лог появится после запуска.

Это демонстрация интерфейса: команды не отправляются на GitHub. Реальные workflow запускаются в вашем репозитории.
